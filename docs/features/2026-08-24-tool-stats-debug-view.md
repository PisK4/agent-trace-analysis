# ATA · 单会话工具调用统计与 Debug 钻取视图

- **日期**：2026-08-24
- **性质**：Web UI 只读增强合集。不改账本 schema、不新增写入路径，纯展示与导航。
- **触发**：回看 trace 时想知道「这次会话调了哪些工具、各调了多少次、哪里在反复失败」，目前只能逐行翻 TOOL 行；评估后把同为只读展示的四个低成本增强并入本批（见「同批捎带项」）。
- **改动范围（本轮只改这些）**：`ata/project.py`、`ata/http.py`、`web/js/`（Timeline 区新模块、nav.js 会话卡片、table.js/app.js 过滤 chips、usage 趋势接线、会话头部元信息条）、`tests/test_query_helpers.py`、`tests/test_http_new_routes.py`、`docs/features/manual-test-guide.md`
- **本轮不改**：schema、四个适配器、seed 数据、跨会话聚合、MCP 分类

## 一句话

Timeline 顶栏一枚常驻徽章 + 点击弹出的单一统计表格，回答四个递进的问题：这次会话调了多少次工具 → 哪个工具失败多 → 哪一次失败 → 为什么失败。形态经高保真 demo（`docs/features/tool-stats-demo/`）与用户排版定稿。

## 问题链与形态的对应

| 级 | 用户问题 | 形态 |
| --- | --- | --- |
| 折叠态 | 这次会话工具用得凶不凶 | 一行摘要：`N tools · M calls · K failed`，K 非零标红 |
| 一级 | 哪个工具失败多 | 每工具一行的状态方块条带 |
| 二级 | 哪一次调用失败 | 点开某工具，看它的调用时间序列 |
| 三级 | 为什么失败 | 点条目跳回轨迹现场，看入参、结果、上下文 |

## 设计

### 1. 落点与默认折叠

模块挂在 Timeline 区，默认折叠。折叠态只有摘要一行；展开才渲染条带和钻取。打开页面不增加视觉负担。

### 2. 一级：状态条带

```
Bash        ■■■■■■■■■■■■■■■■■■■□□□  22 次 · 0 失败
mcp__search ■■■■■■■■□               9 次 · 1 失败
WebFetch    ■■■□                    4 次 · 2 失败
```

| 项 | 口径 |
| --- | --- |
| 一个方块 | 该工具的一次调用，按发生顺序排列 |
| 绿 ■ | `completed` |
| 红 □ | `failed` |
| 黄 | `pending`（进行中的会话会出现） |
| 去重 | 沿用 `list_tools()` 的 latest-wins：同一 `tool_call_id` 只计终态，pending 与终态不双计 |
| 压缩 | 单工具超过约 40 次时，方块压缩为比例条（宽度按成败比例），行尾保留精确计数 |
| 排序 | 按首次出现顺序，不用次数降序——前端每秒轮询，次数降序会让行在实时会话里上下跳 |

### 3. 二级：单工具的调用序列

点一级行展开该工具的全部调用，按时间顺序：

- 初始渲染 5 条，滚到底部追加一批；不做虚拟滚动（零构建前端，几百条的列表增量追加足够）
- 每条显示：状态图标、时间、`duration_ms`、入参首行截断预览（扫一眼就知道是哪次调用，比如 Bash 执行的是哪条命令）

### 4. 三级：跳转到现场

每个调用条目携带 `seq` 作为锚点键（events 表主键之一）。

| 场景 | 动作 |
| --- | --- |
| 目标行已在当前加载窗口 | `scrollIntoView` + 高亮闪烁 |
| 不在窗口 | 取 `?before=<seq+1>&limit=80` 拉取包含它的页，渲染后定位 |
| 点击动机是看细节 | 顺带把 inspector 打开到该调用的 payload tab |

已知边界：锚定的是点击时的最新投影。会话仍在进行时账本会继续更新，跳转后的行内容可能与点击时看到的统计略有出入。本地阅读器场景下接受，写入 manual-test-guide 免得当 bug 报。

### 5. 数据端点

新增 `GET /api/sessions/<sid>/tool-stats`：

```json
{"tools": [{"name": "Bash", "total": 22, "failed": 0,
             "calls": [{"seq": 1042, "ts": "...", "status": "completed",
                        "duration_ms": 311, "text": "ls -la (120 字符内截断)"}]}],
 "summary": {"tools": 12, "calls": 87, "failed": 3}}
```

`text` 是适配器已生成的入参单行描述（`_tool_text(args)`），截断后随行返回，供二级条目做首行预览，不额外解析 payload。

- 服务端实现：复用 `list_tools()` 的去重结果做 Counter（`summarize_tools(recs)`），不重复写去重逻辑
- 不返回 result 全文与入参全文：`/tools` 端点已能取全文，本端点只为计数与导航，几百次调用的会话不该为此拉几 MB
- 不复用 `/tools` 端点扩字段：它缺钻取所需的 `seq` 与入参预览，且 result 全文随行返回；为统计去扩它会改变现有消费者的响应重量
- 不在前端从 `current.rows` 算：那是分页窗口，会漏

## 同批捎带项

评估只读增强候选后，以下四项成本为小、与本模块同属展示与导航层，并入本批。核心评审对象仍是上面的工具统计模块。

| 项 | 做什么 | 数据来源 |
| --- | --- | --- |
| 会话卡片 turns 数 | 左侧列表卡片补显示轮次数。`item.turns` 已传到前端但未渲染（nav.js），属遗漏修补 | boot 现有数据 |
| 表格过滤 chips | 主表按 kind / status 一键过滤，「只看失败」「只看工具」各一枚 chip；与统计模块的红方块互为入口 | `current.rows` 现有字段 |
| 逐轮 token 趋势 | 接入现成 `/usage` 端点（此前前端从未消费）：逐轮 input/output 双色条 + missing_turns 计数显式暴露计量盲区；缓存命中做成列而非独立图——本地中转语料该字段系统性为 null，单独成图只会常年空置 | `/usage` 端点零改动 |
| 会话元信息条 | 并入 Usage 面板首行：agent、轮次数、token 合计、missing 计数。不做总时长与消息/工具计数——那要全量扫描或信已加载窗口，前者超预算后者口径错 | `current.turns` + `/usage` |

## 动手前的前置核实

红方块的可信度取决于各适配器有没有如实写 `status`。Pi 是 live hook 推送，问题不大；Claude / Codex / Droid 是文件 tail 翻译方言，「失败」在各 transcript 里表达不同（如 Claude 的 tool_use 与 tool_result 配对）。实现第一步先核四个适配器实际产出的 status 值域，确认 `failed` 不是永远空集；若某方言拿不到失败信号，该宿主的方块如实全绿并在 manual-test-guide 写明数据边界，不造假红。

## 明确不做的路

| 候选 | 为什么不做 |
| --- | --- |
| MCP 工具按名字前缀分类统计 | 账本无 MCP 来源标记，前缀匹配是启发式；写成统计就是冒充事实判定。等适配器补来源标记字段再做 |
| 按调用次数降序排一级列表 | 实时会话轮询下布局抖动 |
| 前端从 `current.rows` 自算统计 | 分页窗口外的事件会漏，口径错 |
| 虚拟滚动渲染二级列表 | 增量追加够用，虚拟滚动超出本仓零构建前端的复杂度预算 |
| 缓存命中独立趋势图 | 本地中转语料 cache_read/cache_write 系统性为 null（已知盲区），单独成图常年空置；并入 usage 趋势做列 |
| 统计含 duration 分布图 | 本轮只展示单次耗时于二级条目；分布图等有真实需求再说 |

## 验收

| 项 | 通过标准 |
| --- | --- |
| `make test` | 全量通过；`test_query_helpers` 覆盖 `summarize_tools` 的去重与计数；`test_http_new_routes` 覆盖 `tool-stats` 路由 |
| 数字一致性 | 任选一会话：折叠摘要的 calls 数 = 展开后各方块总数之和 = 该会话去重后 TOOL 行数 |
| 失败可见性 | 构造或找到含 failed 调用的会话：红方块数量与 TOOL 行实际失败数一致 |
| 跳转 | 点击二级条目，视口定位到对应 TOOL 行且高亮；目标不在已加载页时也能到达 |
| 服务恢复 | 改完后 `./scripts/install-service.sh restart`，`curl /api/health` 正常 |
| 空态 | 无工具调用的会话不画模块，不出空面板 |
| 会话卡片 | 左侧卡片出现轮次数，数值与会话实际 turn 数一致 |
| 过滤 chips | 点「只看失败」后主表只剩 failed 行；再点还原；与搜索叠加不冲突 |
| usage 趋势 | 有 usage 的会话逐轮双色条可见；missing_turns 非零时计数显式展示而非静默省略；Droid 全 missing 属预期 |
| 元信息条 | agent / 轮次数 / token 合计与账本一致 |
