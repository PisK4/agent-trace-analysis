## Question

Langfuse 给了一个现成思路：回归任务不是手写的脚本，是从真实轨迹里"挑出来存档"的坏案例。每个测试项只需要两样东西：输入（必填）和期望输出（可选，先空着也行）。

所以这张票要回答的问题收窄为：

1. 从一条 Cue 会话里提取测试项，最少存哪几个字段？（候选：首条用户消息全文、当时的系统提示版本、工作区路径；期望输出先不存）
2. 重放时哪些环境因素会让两次运行没法比？逐项查清并标注证据来源（文件路径）：时间敏感内容、外部 API 依赖、凭证、工作区当前状态、模型端随机性。
3. 提取动作做成什么形态最省事：CLI 一条命令从账本导出？还是先手动复制粘贴？

结论决定 T5 的 run 对比能不能建立在真实复跑上。

## Resolution

2026-08-23 调研完成。**结论：Cue 会话可以重放，但做不到逐字复现。对比策略是固定可控项、挑低耦合任务、多次 run 看统计，不追求单次轨迹一致。**

说明：本机没有 `repos/cue` 检出，调研依据改为 Cue 设计档案（`Agent开发/cue/11-pi集成.md`，下称"集成篇"）、本机 `~/.cue` 实物和 ata 账本字段核对。

### 1. 测试项最少存这几个字段

| 字段 | 必要性 | 从哪来 |
| --- | --- | --- |
| `input`：首条用户消息全文 | 必填 | ata 账本第一条 role=user 的 message.upserted（已核实账本里存了全文） |
| `channel`：走的哪条通道 | 必填，先标 unknown | 集成篇第 2 节：三条通道工具白名单完全不同（应答通道有 bash/edit/write，主动通道只读），不知道通道就没法保证重放时白名单一致。轨迹目前判不出通道，靠适配器后续补 |
| `model` / `thinkingLevel` | 必填 | assistant 消息 payload 的 model/effort 字段 |
| `cwd` | 建议 | 账本暂无此字段，导出时手动补；它决定 pi 的资源发现范围（集成篇第 3、11 节） |
| `injection_snapshot`：当时的注入文本 | 开了上下文注入就必填 | 集成篇第 12 节：注入内容实时生成无法复原，唯一办法是把当时注入的文本一起存档，重放时作固定前缀 |
| `source_session_id` | 建议 | 回链原始轨迹 |
| `expected_output` | 可选 | 先空着 |

提取时要过滤内部会话。账本里已发现两类：标题自动生成任务（title 是一段 prompt 原文）、`subagent-delegate-*` 子会话。信号是标题模式，导出逻辑按此排除。

### 2. 让对比失真的因素，按可控性分三档

**可控（记录下来就能固定）**：model 与 thinkingLevel（集成篇第 3 节，显式传入）；压缩与重试参数（第 8 节，settingsManager 覆盖）；单轮工具调用上限 8 次（第 5 节，tool_call 钩子）；cwd 与 agentDir。

**半可控（同机同期基本稳定）**：凭证（Keychain 注入内存存储，同机复跑无差）；系统提示词与工具清单版本（随 Cue 发版变，跨版本对比要标注版本）。

**不可控（真正的噪声源）**：
- 记忆库状态：`cue_query_memory` 读的记忆随使用增长，同一问题不同日期答案不同；
- 采集数据：`cue_query_timeline` 读采集层的 timeline 与 repo_snapshots，数据随时间变（集成篇 4.3 节）；
- 屏幕观察注入：内容实时生成（第 12 节）；
- web_search 外部结果（用户开启时）；
- 模型端随机性。

**缓解三条**：回归任务集优先挑不依赖记忆与实时采集的任务；指标对比用多次 run 取均值而非单次；失败类指标（工具失败率、步数膨胀、循环）对噪声天然比输出质量鲁棒，优先建这几种。

### 3. 提取形态

语料现在只有个位数，首版手动复制粘贴足够；等语料上量再做 `read export <sid>` 导出命令。不预先实现。
