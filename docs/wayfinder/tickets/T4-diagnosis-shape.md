## Question

失败模式检测放在哪一层？

- A：便捷端点扩展（服务端预计算失败信号）；
- B：Skill 内置诊断清单（Agent 用通用读取接口自己跑检查表）；
- C：独立分析 agent run（专门的分析会话批量扫账本出报告）；
- D：诊断结果存成结构化标注（参考 Langfuse 的 score：一个名字 + 一个值 + 一个类型，挂到会话上）。D 和 A/B/C 不互斥，可以组合——不管用什么方式检测，结果都可以落成标注，方便以后统计"这类失败出现了几次、是在变多还是变少"。注意标注有两个来源：机器检测的过程信号，和用户主观打的质量标注（见「人工标注机制」票）；本票裁决的是机器那一路怎么落，人标那路归 T9。

用 T2 盘点出的失败模式和它们的检测成本来裁决。回答时要给出各方案对"诊断→干预→复验"这一圈的延迟影响。
